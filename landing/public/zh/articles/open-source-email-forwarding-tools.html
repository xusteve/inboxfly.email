开源邮件转发工具推荐与对比：选型指南

开源邮件转发工具怎么选？对比基于 Cloudflare 的轻量转发器与完整邮件服务器，从架构、成本、许可协议与可维护性给出选型建议。

想自己跑一个开源邮件转发工具，选择分为两类：完整邮件服务器（Postfix 系）与基于 Cloudflare 的轻量转发器。对大多数人来说，第二类更合适。

候选对比

工具架构协议适合
InboxFlyCloudflare Worker + D1 + R2MIT带管理面板、归档与统计的转发
ForwardEmailNode 自托管/托管MIT简单的别名与转发
Postfix + aliases完整邮件服务器GPL 等已经跑服务器、还要 IMAP 的用户

选型看四点

  • 邮件存在哪——你的 Cloudflare 账号里的 Worker，数据留在你账号；VPS 则要自己运维机器。
  • 运维成本——Cloudflare 免费额度覆盖每天 10 万请求；VPS 有月费还要打补丁。
  • 管理界面——能不进 SSH 就改规则、搜邮件、看统计吗？

为什么基于 Cloudflare 的方案更适合多数人

基于 Cloudflare 的开源邮件转发工具兼具两头优势：自托管（你的账号、你的数据）与有管理（面板代替配置文件）。CF 里保留一条 catch-all，工具负责匹配、筛选、存储与计数——MIT 协议、零服务器维护。

InboxFly 正是这样：开源邮件转发 + 真正的管理面板，几分钟部署到自己的 Cloudflare 账号。

常见问题

基于 Cloudflare 的转发可靠吗？ 可靠——Email Routing 是生产级基础设施，Worker 同步处理邮件并带 fail-open 兜底。

能从 ForwardEmail 或 Postfix 迁移吗？ 通常可以：MX 指向 Cloudflare Email Routing，导入规则，更新目标地址即可。
