1. 로컬에서 빠르게 시작 (3분)

로컬 환경은 실제 메일 수신이 불가하지만 패널과 파이프라인 전체를 시험할 수 있습니다("시뮬레이트"로 테스트 데이터 주입):

git clone https://github.com/INBOXFLY-REPO-PLACEHOLDER/inboxfly.git
cd inboxfly && npm install
npm run dev          # 启动在 http://localhost:8787
  • 첫 방문 시 설정 마법사가 열립니다. 로컬 SETUP_TOKEN은 inboxfly-local-setup(.dev.vars 참조).
  • 마법사 3단계(Email Routing 활성화)는 로컬에서 건너뜁니다.
  • 패널에서 "시뮬레이트" 클릭: 프로덕션과 동일한 파이프라인(매치→필터→판정→저장→통계)으로 테스트 메일을 주입하며 실제 전달만 생략합니다.
  • 리셋: rm -rf .wrangler 후 재시작, 다시 마법사를 실행합니다.

2. Cloudflare에 배포

npx wrangler login
npx wrangler deploy           # Worker + 静态面板 + D1 + R2 + KV + Cron
npx wrangler secret put SETUP_TOKEN    # 首次运行向导用的初始化令牌
  • D1 테이블은 첫 패널 방문 시 자동 생성됩니다 — 수동 SQL 불필요(폴백으로 npx wrangler d1 execute inboxfly --remote --file schema.sql 실행 가능).
  • 패널 기본 주소는 https://inboxfly.<서브도메인>.workers.dev입니다. Workers → Domains & Routes에서 커스텀 도메인(예: panel.yourdomain)을 연결하세요.
  • Cron 트리거(매일 03:00 UTC R2 정리)는 배포 시 자동 등록됩니다.
  • robots.txt에 Disallow: /가 포함되어 사설 패널이 인덱싱되지 않습니다.

3. 초기 마법사 (5단계)

배포 후 패널 URL을 열고 마법사를 따릅니다. 각 단계에서 "이유"와 "위험"을 설명합니다:

  1. 배포자 신원 확인: SETUP_TOKEN 입력(배포 출력에만 표시, 설정 후 무효화) — 패널 탈취 방지.
  2. 관리자 자격 증명 생성: 사용자 이름 + 8자 이상 비밀번호(PBKDF2 해시, 복구 불가).
  3. Email Routing 활성화: 로컬은 건너뜁니다. 프로덕션에서는 Cloudflare 대시보드 안내를 따릅니다(다음 절).
  4. 수신 주소 추가: 실제 메일함(예: Gmail)을 입력하고 Cloudflare 확인을 완료합니다.
  5. 첫 규칙 생성: 기본값 *@yourdomain → 전달 → 확인된 수신처, fail-open 폴백으로 설정됩니다.

4. 메일 라우팅 활성화 (도메인별)

세 가지가 필요합니다: Email Routing 마스터 스위치, Worker를 가리키는 catch-all, 확인된 수신처. 두 가지 방법:

방법 A · 패널 자동화 (권장)

설정 → 도메인에서 CF API 토큰을 저장하면 도메인별 "전달 활성화" 버튼이 나타납니다. 패널이 자동으로: MX 충돌 감지(레코드별 확인을 위해 나열) → Email Routing 활성화 → 권장 MX/SPF DNS 추가 → catch-all을 InboxFly Worker로 설정.

토큰 권한(실측): Account → Workers Scripts / D1 / KV / R2 Storage(편집) + Account Settings(읽기); Zone → Zone(읽기), DNS(편집), Email Routing Rules(편집), Zone Settings(편집). 참고: Email Routing 활성화/조회에는 "Zone Settings" 그룹이 필요하며 "Email Routing Rules"만으로는 부족 — 둘 다 체크하지 않으면 Authentication error.

방법 B · Cloudflare 대시보드에서 수동

대시보드 → 존 → Email → Email Routing → 활성화(MX 교체 확인) → Catch-all 주소 → 작업 "Send to a Worker" → inboxfly 선택. 이후 패널을 새로고침하면 도메인 상태가 모두 초록으로.

5. 수신 주소

  • 수신 페이지에서 실제 메일함 추가 → Cloudflare가 확인 이메일 자동 발송 → 수신자가 클릭하면 자동으로 "확인됨"으로.
  • 수신처는 계정 단위: 한 번 확인하면 모든 도메인에서 사용.
  • 첫 확인 주소가 fail-open 폴백이 됩니다: Worker가 내부 오류 시 시도하여 무음 유실을 방지.
  • 규칙이 참조하는 주소는 삭제 불가(먼저 규칙을 수정하라는 안내).

6. 라우팅 규칙

규칙 페이지는 Cloudflare 네이티브 라우팅 페이지를 따릅니다: 통합 규칙 표 + 끝에 고정된 "📌 Catch-all" 폴백 행.

규칙 만들기

  • 이메일 매치: 왼쪽 이름(예: info, support) + @ + 오른쪽 도메인 선택. 이름 비움 = 도메인 전체.
  • 작업: 이메일로 보내기(확인된 수신처로 전달) / 폐기(무음) / 반송(InboxFly 확장 — SMTP 수준 거부, 네이티브에는 없음).
  • 고급 필터(선택 확장): 발신자 블랙리스트(한 줄에 하나: 주소 / @도메인 / /정규식/), 제목 정규식, 크기 상한(≤25MB), 첨부 조건.

평가 순서

정확 규칙 → catch-all 규칙, 그룹 내 정렬, 첫 매치 우선. 미매치는 Catch-all 행(기본 수신처로 전달/반송/폐기).

중요: Cloudflare 대시보드에서 라우팅 규칙을 수동 생성하지 마세요 — 네이티브 규칙이 catch-all보다 우선하며 InboxFly를 우회합니다(복사본도 통계도 없음). 기존 네이티브 규칙은 설정 → 도메인에서 가져오세요.

7. 일상 관리

  • 메일 목록: 도메인/상태/키워드 필터, 다중 선택 일괄 삭제 지원.
  • 메일 상세: 샌드박스 HTML 렌더링(원격 이미지 차단), 텍스트 표시, 첨부 다운로드, 원본 MIME(.eml).
  • 통계: 상태(전달/차단/폐기/반송/오류)와 도메인별, 14일 추이. "전달됨" = Cloudflare가 전달을 수리함을 의미, 최종 배치는 관측 불가.
  • 레이아웃: 우상단 버튼으로 사이드바/헤더 모드 전환. 모바일은 항상 헤더 레이아웃.

8. 저장소와 할당량

  • 복사본(HTML/텍스트/원본 MIME)과 첨부는 내 R2에 저장, 기본 30일 보관, 매일 03:00 UTC 자동 정리(설정에서 조정 가능, 수동 정리 지원).
  • 필터 차단 메일은 기본 메타데이터만 저장(스팸 폭풍 방지). 필요 시 본문 저장 활성화.
  • 30일 R2 예상량이 9GB를 초과하면 경고 배너가 나타나며 원클릭으로 메타데이터 전용 모드 전환(전달은 영향 없음).

9. 보안

  • Cloudflare Turnstile: 설정 → 봇 보호에서 Site/Secret 키를 붙여넣고 활성화 — 로그인 시 인간 확인 표시(서버 측 siteverify). 로컬 테스트용 공식 테스트 키: Site 1x00000000000000000000AA / Secret 1x0000000000000000000000000000000AA(항상 통과).
  • 관리자 계정: 설정 → 관리자 계정. 사용자 이름/비밀번호 변경 시 다른 세션 모두 무효화.
  • 세션: 기본 24시간, "로그인 유지" 시 30일. 변경 작업은 CSRF 보호, 로그인은 속도 제한.
  • 메일 콘텐츠 안전: 본문은 iframe 샌드박스(스크립트 비활성)로 렌더링, 서버 측 살균으로 위험 마크업 제거, 원격 이미지 기본 차단.

10. 테마/언어/PWA

  • 3테마 × 라이트/다크: Fluid Glass(기본)/Minimal/Playful, 각각 완전한 다크 버전. 기본 시스템 추적.
  • 10개 언어: 브라우저에서 자동 감지. 지구본 아이콘으로 언제든 전환.
  • PWA 설치: Android Chrome → 메뉴 "앱 설치"(또는 설정 버튼). iOS Safari → 공유 → "홈 화면에 추가".

11. 알려진 제한

  • 로컬은 실제 메일 수신 불가(Email Routing은 프로덕션 기능) — 로컬에서는 "시뮬레이트" 사용.
  • "전달됨"은 Cloudflare가 수리했음을 의미. 스팸 폴더 배치는 관측 불가. 필요 시 수신 메일함에서 도메인을 허용하세요.
  • 같은 도메인에서 Cloudflare 네이티브 규칙과 InboxFly를 혼용하지 마세요(패널을 우회합니다). 존 단위 병행은 무방.
  • 메시지당 25MiB(Cloudflare 플랫폼 제한).

12. 제거와 정리

  1. 패널의 CF API 토큰을 해지(대시보드 → API 토큰) — 전달 파이프라인은 계정에서 독립 실행되며 계속 동작합니다. 패널 자동화는 축소.
  2. 전달 중지: 대시보드 → Email Routing → Catch-all 또는 전체 비활성화.
  3. 리소스 삭제: Workers → inboxfly; D1 → inboxfly; R2 → inboxfly; KV → 네임스페이스.
여기 없는 내용은 GitHub Issue로 알려주세요(저장소 링크는 제품 페이지에).
