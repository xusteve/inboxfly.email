Документация InboxFly

1. Быстрый старт локально (3 мин)

Локально реальные письма не принимаются, но можно протестировать весь панель и конвейер (данные через «Симулировать»):

git clone https://github.com/INBOXFLY-REPO-PLACEHOLDER/inboxfly.git
cd inboxfly && npm install
npm run dev          # 启动在 http://localhost:8787
  • Первый визит открывает мастер настройки; локальный SETUP_TOKEN — inboxfly-local-setup (см. .dev.vars).
  • Шаг 3 мастера (Включить Email Routing) локально пропускается.
  • В панели нажмите «Симулировать»: он создаёт тестовые письма через точно тот же производственный конвейер (совпадение → фильтр → решение → хранение → статистика), пропуская только реальную доставку.
  • Сброс: rm -rf .wrangler, перезапустите и пройдите мастер заново.

2. Развернуть на Cloudflare

npx wrangler login
npx wrangler deploy           # Worker + 静态面板 + D1 + R2 + KV + Cron
npx wrangler secret put SETUP_TOKEN    # 首次运行向导用的初始化令牌
  • Таблицы D1 создаются автоматически при первом посещении панели — ручной SQL не нужен (или выполните npx wrangler d1 execute inboxfly --remote --file schema.sql как запасной вариант).
  • Панель по умолчанию доступна на https://inboxfly.<ваш-поддомен>.workers.dev; привяжите пользовательский домен (напр. panel.yourdomain) в Workers → Domains & Routes.
  • Cron Trigger (ежедневная очистка R2 в 03:00 UTC) регистрируется автоматически при развёртывании.
  • robots.txt содержит Disallow: /, чтобы частная панель не индексировалась.

3. Мастер первой настройки (5 шагов)

Откройте URL панели после развёртывания и следуйте мастеру. Каждый шаг объясняет «зачем» и «риски»:

  1. Проверка личности развернувшего: введите SETUP_TOKEN (появляется только в выводе развёртывания, аннулируется после настройки) для защиты от захвата панели.
  2. Создать учётные данные администратора: имя пользователя + пароль ≥8 символов (хэш PBKDF2, невосстановим).
  3. Включить Email Routing: локально пропустить; в продакшене следовать инструкции в дашборде Cloudflare (следующий раздел).
  4. Добавить адрес получателя: введите свой реальный почтовый ящик (напр. Gmail) и завершите подтверждение Cloudflare.
  5. Создать первое правило: по умолчанию *@yourdomain → переслать → подтверждённый адрес и назначает его запасным fail-open.

4. Включение маршрутизации почты (для каждого домена)

Нужны три вещи: главный переключатель Email Routing, catch-all на Worker и подтверждённый адрес. Два способа:

Вариант A · Автоматизация через панель (рекомендуется)

После сохранения токена API CF в Настройки → Домены появляется кнопка «Включить пересылку» для каждого домена. Панель: обнаруживает конфликты MX (перечисляет для подтверждения каждой записи) → включает Email Routing → добавляет рекомендуемые MX/SPF DNS → направляет catch-all на Worker InboxFly.

Права токена (проверено): Аккаунт → Workers Scripts / D1 / KV / R2 Storage (изменение) + Настройки аккаунта (чтение); Зона → Zone (чтение), DNS (изменение), Email Routing Rules (изменение), Zone Settings (изменение). Внимание: включение/запрос Email Routing требует группу «Zone Settings», а не «Email Routing Rules» — отметьте обе, иначе Authentication error.

Вариант B · Вручную в дашборде Cloudflare

Дашборд → зона → Email → Email Routing → Включить (подтвердить замену MX) → адрес catch-all → действие «Send to a Worker» → выбрать inboxfly. Затем обновите панель; все проверки станут зелёными.

5. Адреса получателей

  • Добавьте свой реальный почтовый ящик на странице Получатели → Cloudflare автоматически отправляет подтверждение → после клика получателя панель переходит в «Подтверждён».
  • Адреса — уровень аккаунта: подтвердите один раз, используйте везде.
  • Первый подтверждённый адрес становится запасным fail-open: Worker пробует его при внутренних ошибках, чтобы избежать тихой потери.
  • Адреса, на которые ссылаются правила, нельзя удалить (вас попросят сначала изменить правило).

6. Правила маршрутизации

Страница правил повторяет нативную страницу маршрутизации Cloudflare: единая таблица с фиксированной строкой «📌 Catch-all» в конце.

Создание правила

  • Совпадение email: имя слева (напр. info, support) + @ + список доменов справа; пустое имя = весь домен.
  • Действие: Отправить на email (переслать на подтверждённый адрес) / Удалить (тихо) / Вернуть (улучшение InboxFly — отказ на уровне SMTP, нативно нет).
  • Расширенные фильтры (опционально): чёрный список отправителей (по одному в строке: адрес / @домен / /regex/), regex темы, лимит размера (≤25МБ), условие по вложениям.

Порядок оценки

Точные правила → catch-all, отсортированы в группе, первое совпадение побеждает. Несоответствующие письма идут в строку Catch-all (переслать по умолчанию / вернуть / удалить).

Важно: не создавайте правила маршрутизации вручную в дашборде Cloudflare — нативные правила имеют приоритет над catch-all и обходят InboxFly (ни копий, ни статистики). Импортируйте существующие нативные правила через Настройки → Домены.

7. Ежедневное управление

  • Список писем: фильтр по домену / статусу / ключевому слову; пакетное удаление с множественным выбором.
  • Детали письма: рендер HTML в песочнице (удалённые изображения заблокированы), текстовый вид, скачивание вложений, исходный MIME (.eml).
  • Статистика: по статусу (переслано/заблокировано/удалено/возвращено/ошибка) и домену, тренды за 14 дней. «Переслано» = Cloudflare принял пересылку; итоговое размещение ненаблюдаемо.
  • Раскладка: кнопка справа вверху переключает режимы боковая панель / шапка; на мобильных всегда шапка.

8. Хранилище и квоты

  • Копии (HTML/текст/исходный MIME) и вложения живут в вашем R2, по умолчанию 30 дней с ежедневной автоочисткой в 03:00 UTC (настраивается; доступна ручная очистка).
  • Заблокированные фильтром письма хранят только метаданные по умолчанию (защита от спам-шторма); включите полное хранение при необходимости.
  • Появляется предупреждение, когда оценка R2 за 30 дней превышает 9ГБ, с переключением в один клик на режим «только метаданные» (пересылка не затрагивается).

9. Безопасность

  • Cloudflare Turnstile: Настройки → Защита от ботов, вставьте ключи Site/Secret и включите — при входе появляется проверка «человек ли вы» (siteverify на сервере). Для локальных тестов официальные тестовые ключи: Site 1x00000000000000000000AA / Secret 1x0000000000000000000000000000000AA (всегда успех).
  • Аккаунт администратора: Настройки → Аккаунт администратора; изменение имени/пароля аннулирует все другие сессии.
  • Сессии: 24ч по умолчанию, 30 дней с «запомнить меня»; защита CSRF на изменениях, ограничение входа.
  • Безопасность содержимого: тела рендерятся в iframe-песочнице (скрипты отключены), серверная санитизация удаляет опасную разметку, удалённые изображения заблокированы по умолчанию.

10. Темы / язык / PWA

  • 3 темы × светлая/тёмная: Fluid Glass (по умолчанию) / Minimal / Playful, каждая с полной тёмной версией; по умолчанию следует системе.
  • 10 языков: автоопределение из браузера; переключение в любой момент через иконку глобуса.
  • Установка PWA: Android Chrome → меню «Установить приложение» (или кнопка в настройках); iOS Safari → Поделиться → «На экран «Домой»».

11. Известные ограничения

  • Локально нельзя получать реальные письма (Email Routing — производственная функция) — используйте «Симулировать».
  • «Переслано» означает, что Cloudflare принял; размещение в спаме ненаблюдаемо. При необходимости добавьте домен в белый список в почте получателя.
  • Не смешивайте нативные правила Cloudflare и InboxFly на одном домене (они обходят панель); сосуществование на уровне зоны допустимо.
  • 25МиБ на сообщение (ограничение платформы Cloudflare).

12. Удаление и очистка

  1. Отзовите токен API CF панели (дашборд → Токены API) — конвейер пересылки работает независимо в вашем аккаунте и продолжает работу; автоматизация панели деградирует.
  2. Остановить пересылку: дашборд → Email Routing → отключить Catch-all или всю службу.
  3. Удалить ресурсы: Workers → inboxfly; D1 → inboxfly; R2 → inboxfly; KV → пространство имён.
Если здесь чего-то нет, откройте тикет на GitHub (ссылка на репозиторий на странице продукта).
